# x-to-ean13

Generates a deterministic EAN-13 barcode for each word in a CSV file. Codes are
allocated sequentially and recorded in a **ledger file**, so the same word
always maps to the same EAN-13 across runs and no two words ever collide.

## ⚠️ Internal use only — not a valid GTIN for open trade

The default company prefix, `200`, falls in the GS1 **restricted distribution**
range (`020`–`029`, `040`–`049`, `200`–`299`). GS1 reserves this range for use
*inside a single company* and explicitly does not guarantee it is globally
unique. Barcodes generated by this tool with the default prefix:

- Must **never** be submitted to retailers, marketplaces, GDSN, or any GS1
  validation service (Verified by GS1, etc.) — they will be rejected or, worse,
  silently collide with another company's internal codes.
- May be misread by some point-of-sale systems, which treat the `02x`/`20x`
  range as *variable-measure* (price- or weight-embedded) items and decode
  part of the code as a price rather than an identifier.
- Are fine for closed-loop internal use: your own warehouse systems, internal
  POS, asset tags, or RFID/SGTIN data that never leaves systems you control.

If you need a barcode valid for open trade, you must license a real GS1
Company Prefix from your GS1 Member Organisation and pass it via `-prefix`.

## Requirements

- Go 1.26+ (see `go.mod`)
- [`dlv`](https://github.com/go-delve/delve) if you want to debug (`go install github.com/go-delve/delve/cmd/dlv@latest`)

## Build

Compiles a binary named `x-to-ean13` in the current directory:

```sh
go build -o x-to-ean13 .
```

### Build for Windows

Go cross-compiles out of the box, so you can build a Windows binary from macOS,
Linux, or Windows itself by setting `GOOS`/`GOARCH`:

```sh
# amd64 (most PCs)
GOOS=windows GOARCH=amd64 go build -o x-to-ean13-amd64.exe .

# arm64 (Windows on Arm)
GOOS=windows GOARCH=arm64 go build -o x-to-ean13-arm64.exe .

# 386 (32-bit)
GOOS=windows GOARCH=386 go build -o x-to-ean13-386.exe .
```

On native Windows (PowerShell or `cmd.exe`), just run:

```powershell
go build -o x-to-ean13.exe .
```

## Run without building (compile + run in one step)

```sh
go run . [-header] [-prefix <company-prefix>] [-output <file>] [-ledger <file>] <csv-file>
```

## Usage

| Flag       | Default                  | Description                                                  |
|------------|--------------------------|----------------------------------------------------------------|
| `-header`  | `false`                  | Set if the input CSV has a header row to skip                |
| `-prefix`  | `200`                    | Company prefix used when generating the EAN-13               |
| `-output`  | `<input>.ean13.csv`      | Output CSV file path                                          |
| `-ledger`  | `<input>.ledger.csv`     | Ledger file recording word→EAN-13 allocations                 |

The first column of each input row is treated as the word. The output CSV has
two columns: the word and its generated `ean13`. If `-header` is set, the
output header reuses the source's first-column name and appends `ean13`.

Example:

```sh
./x-to-ean13 -header -prefix 200 words.csv
# ean13 file generated. N row(s) to words.ean13.csv (N newly allocated, 0 reused from words.ledger.csv)
```

### The ledger

Each run loads the ledger file, allocates a fresh, never-before-used EAN-13
for every word not already in it, saves the ledger, then writes the output
CSV. This is what makes codes both **stable** (rerunning with the same word
list produces the same barcodes) and **collision-free** (every word gets a
distinct item reference) — properties a hash of the word alone cannot
guarantee, since uniqueness depends on everything already issued, not just
the current input.

The ledger has the same two-column (`word`, `ean13`) shape as the output CSV,
so you can seed it from a previous run's output — e.g. `cp old.ean13.csv
new.ledger.csv` — and every barcode already handed out (printed on labels,
stored in another system) will be preserved exactly, with only new words
getting new codes.

Changing `-prefix` between runs against the same ledger is rejected: the
ledger is tied to the prefix it was built with.

## Debug

Using [Delve](https://github.com/go-delve/delve) from the command line, passing
program flags after `--`:

```sh
dlv debug . -- -header words.csv
```

Common Delve commands once stopped at a breakpoint: `b main.run` (set a
breakpoint), `c` (continue), `n` (step over), `p <var>` (print a variable),
`bt` (stack trace).

### VS Code

Add a launch configuration (`.vscode/launch.json`) such as:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug x-to-ean13",
      "type": "go",
      "request": "launch",
      "mode": "auto",
      "program": "${workspaceFolder}",
      "args": ["-header", "words.csv"]
    }
  ]
}
```

Then set breakpoints in the editor and use "Run and Debug".
